# AI-E랩 연구 여정 웹앱

AI교육 성과주간 '곁' 체험 구역용 단일 HTML 웹앱입니다. GitHub Pages로 배포됩니다.

## 연구회 카드 내용 채우기

구글 폼 응답 CSV를 받으면 아래 한 줄로 카드 데이터를 다시 채웁니다. 대표교사 성함·이메일은 넣지 않고, 카드에 보이는 내용만 추립니다.

```bash
python3 -I tools/cards_from_csv.py "응답.csv"
```

- `data/cards.json`이 다시 쓰이고, `index.html`의 `/* CARDS:BEGIN */ … /* CARDS:END */` 사이가 바뀝니다.
- 연구회명은 `index.html`의 `G` 배열(폼 드롭다운과 같은 이름)과 글자 그대로 맞아야 합니다.
- 응답 CSV 자체는 개인정보가 있으므로 저장소에 넣지 않습니다.

## 연구회 카드 그림 넣기

연구회가 낸 카드 그림은 번호(폼 드롭다운 순번, 1~20)를 붙여 등록합니다. 2:3 비율로 줄여 `assets/cards/NN.webp`로 저장하고 `index.html`의 그림 목록을 다시 씁니다.

```bash
python3 -I tools/card_art.py 08=그림.webp 01=다른그림.png
```

그림이 없는 연구회는 코드로 그린 기본 카드가 나옵니다.

## 글꼴

글꼴은 외부 서버가 아니라 `assets/fonts`에서 불러옵니다. 행사장 네트워크가 구글 글꼴 서버를 막아도 같은 글씨가 나옵니다. 파일은 자주 쓰는 한글 2,350자와 `index.html`에 실제로 나오는 글자만 남겨 줄인 것입니다. 쇼릴·트레일러 전용인 Black Han Sans와 Nanum Pen Script는 화면에 나오는 글자만 담았습니다.

문구나 카드 내용을 고친 뒤 새 글자가 생기면 다시 만듭니다.

```bash
pip install fonttools brotli
```

```bash
python3 tools/subset_fonts.py <Fontsource 패키지를 푼 폴더>
```

다섯 글꼴 모두 SIL Open Font License 1.1이며, 라이선스 전문은 `assets/fonts/licenses`에 있습니다.

## 올리기 전 점검

내용을 고치거나 연구회를 추가한 뒤에는 아래 점검을 돌립니다. 외부 네트워크를 막은 상태로 페이지를 열어, 카드 20장의 모든 단계·주제 화면(화면 크기 3종), 실제 클릭 경로, 트레일러 20개, 다크 모드, 움직임 줄이기, 3분 무입력 복귀를 확인합니다. 3~4분쯤 걸리고, 하나라도 어긋나면 `FAIL`로 표시됩니다.

```bash
npm install --no-save playwright
```

```bash
npx playwright install chromium
```

```bash
node tools/check.js
```

실제 디벗 화면의 터치감과 속도, 행사장 네트워크는 이 점검으로 확인되지 않으니 현장 기기에서 한 번 직접 눌러 보아야 합니다.

## 오프닝 영상

오프닝의 바탕 영상 `assets/opening.webm`(2.4 MB)과 `assets/opening.mp4`(3.7 MB)는 같은 내용의 두 가지 형식입니다. 브라우저가 재생할 수 있는 쪽을 고릅니다. 영상을 받지 못하면 코드로 그린 바탕이 대신 나옵니다.

- Higgsfield로 세 편을 만들어 12.9초로 이어 붙였습니다(1920×1080, 초당 30장, 소리 없음). 화면 묘사만으로 만들었고 연구회 자료는 올리지 않았습니다.
  1. 카드 한 장이 여러 장으로 늘어나는 장면(Kling 3.0, 앞 5초만 씀).
  2. 카드들이 소용돌이를 그리며 하나의 고리로 포개지는 장면(Kling 4.0, 8초). 1의 마지막 장면을 첫 장면으로, 따로 만든 또렷한 정지 그림(포개진 고리)을 끝 장면으로 정해 그 사이를 만들었습니다.
  3. 빛 한 점에서 물결 같은 고리가 퍼지는 장면(Kling 3.0, 5.65초부터 씀). 2와는 0.3초 겹쳐 넘깁니다.
- 글만으로 "작은 카드 수십 장이 빠르게 모이는 장면"을 만들면 카드가 휘고 뭉개집니다. 다시 만들 때도 2처럼 처음과 끝 장면을 또렷한 그림으로 정해 주는 방식을 씁니다.
- 속도는 원본 한 장면이 화면 한 장면에 그대로 대응하도록 1.25배를 기본으로 했습니다(1의 처음 1.5초와 2의 마지막 2초만 더 빠르게).
- 한글 글자와 연구회의 실제 카드는 영상에 들어 있지 않고 `index.html`이 그 위에 그립니다. 그래서 문구나 카드를 바꿔도 영상을 다시 만들 필요가 없습니다.
- 영상의 길이나 장면 시각을 바꾸면 `index.html`의 `VEND`, `T_MAP`, `T_SAY`, `T_LOCK`과 `reelText`의 시각을 함께 맞춰야 합니다.

## 시작 화면 배경의 불빛

시작 화면의 배경 그림 `assets/christmas-atrium.webp`은 그대로 두고, 그 안의 불빛(창문, 조명, 화환의 전구)만 따로 뽑은 `assets/atrium-glow-a·b·c.webp`를 위에 겹쳐 은은하게 밝혔다 줄입니다. 배경 그림을 바꾸면 아래 도구로 다시 만듭니다.

```bash
pip install pillow numpy
```

```bash
python3 tools/atrium_glow.py
```

밝기와 빠르기는 `index.html`의 `glowA`(창문·큰 조명), `glowB`(작은 전구)에서 조절합니다.

## 입장 전환 영상

시작 화면에서 여정으로 들어갈 때 나오는 `assets/enter.webm`(1.9 MB)과 `assets/enter.mp4`(1.6 MB)입니다. 금빛이 아트리움 안쪽으로 날아가고 카메라가 따라가다 빛 속으로 들어갑니다. 받지 못했으면 코드로 그리는 전환이 대신 나옵니다.

- 시작 화면의 배경 그림 `assets/christmas-atrium.webp`에서 장식 테두리를 뺀 가운데 1316×740 영역을 첫 장면으로 주고 Higgsfield(Kling 3.0)로 5초를 만든 뒤 1.25배속으로 4초에 맞췄습니다.
- 그래서 시작 화면을 그 영역 크기까지 살짝 당기면 영상의 첫 장면과 정확히 겹칩니다. 배경 그림을 바꾸면 영상도 다시 만들어야 하고, `index.html`의 `EV`(영역 크기, 마지막 장면의 빛 위치)도 맞춰야 합니다.
